# Backtest migrasi RHI — 6 November 2026

## Kesimpulan

**Belum memenuhi klaim seluruh fitur dan integrasi bekerja 100%.** Inventaris baseline frontend lengkap. Ditemukan 21 file sumber backend yang belum masuk repo migrasi; file tersebut sudah dipulihkan dari arsip sumber. Fungsi yang sedang berjalan sebelumnya tetap tersimpan di delapan bundle runtime VPS. Ditemukan dan diperbaiki juga CORS gateway UAT yang menghalangi login dan pembacaan REST dari browser lokal.

Tiga halaman percakapan masih placeholder sejak aplikasi asal. Integrasi eksternal, backup Drive, dan sinkronisasi terakhir masih memiliki pekerjaan terbuka. Pemeriksaan visual dua halaman tersisa telah diselesaikan pada tindak lanjut refactor di bawah. Pengujian ini tidak mengaktifkan cutover; staf tetap memakai aplikasi lama.

## Lingkungan dan kelengkapan

- Baseline frontend produksi: `5f406e0dff49a1c09f3a7c19b26fdf57c947da30`.
- 61 definisi rute, 49 halaman kanonis; tidak ada rute baseline yang hilang.
- Pada audit awal sebelum refactor, 297 file frontend identik; lima perbedaan ditinjau: banner preview/UAT, stylesheet banner, origin undangan pengguna, normalisasi URL Functions, serta endpoint ekspansi tautan peta. Tidak ada file frontend baseline yang hilang.
- Delapan fungsi backend tercatat dengan versi/JWT bundle; seluruh entrypoint dan import relatif tersedia setelah pemulihan 21 file. Semua sumber backend lulus pemeriksaan sintaks TypeScript.
- Sumber bersama memiliki beberapa varian arsip per fungsi. Pemulihan file **bukan bukti bahwa setiap bundle dapat direproduksi dari satu pohon sumber ini**. Runtime mempertahankan bundle per fungsi yang telah diverifikasi; audit ini tidak menggantinya.
- UAT memakai database, Auth/JWT, Storage, Realtime, dan jaringan terpisah. Kredensial provider UAT berupa nilai uji; pengiriman eksternal dan scheduler tidak diaktifkan.
- Rekonsiliasi snapshot sebelumnya mencakup hash seluruh tabel sumber berisi data dan seluruh objek Storage. Ini membuktikan salinan pada waktu snapshot, bukan transaksi baru yang terus masuk ke aplikasi lama.

## Reproduksi

```sh
node scripts/audit-migration-coverage.mjs
npm run smoke:core-contracts
npm run typecheck:phase4

node scripts/smoke-uat-cors.mjs

File kredensial serta respons bisnis tidak dimasukkan ke Git. Akun browser uji, session, dan fixture suite tambahan telah dibersihkan.

## Tindak lanjut: modularisasi dan regresi

Refactor dilakukan pada sumber frontend lokal, tanpa mengganti bundle backend atau membuka input pada preview publik. Ini merupakan modularisasi kerangka aplikasi dan workspace; bukan penulisan ulang seluruh modul bisnis.

- `AppLayout` turun dari 918 menjadi 568 baris: pemilihan halaman/lazy imports dipindah ke `AppPageContent`, aturan akses ke `appLayoutAccess`, dan skeleton loading ke `PageLoadingState`. Penjagaan izin tetap dilakukan sebelum halaman dipasang; semua case halaman baseline masih tersedia.
- `WorkspaceFrame` menjadi kerangka bersama halaman percakapan dan monitoring iklan untuk judul, deskripsi, badge, metrik, aksi, filter, dan konten. Wrapper domain tetap tersedia agar pemanggil tidak perlu berubah.
- `AdsMonitoringFilters` memisahkan filter interaktif dari kerangka tampilan. Pemilih tanggal tidak lagi muncul dua kali ketika panel filter tersedia. Select platform/advertiser/mode dan switch perbandingan mempunyai nama aksesibel.
- `PageErrorBoundary` menjaga navigasi ketika halaman/lazy chunk gagal, dengan aksi muat ulang. Loading diberi status aksesibel. Placeholder menyatakan fitur belum tersedia tanpa menjanjikan jadwal penyelesaian.
- Scope ESLint diperluas ke komponen workspace dan filter yang diubah.

Validasi sesudah refactor: enam suite TypeScript, lint, build, 13 kontrak inti, guard deployment, inventaris rute/import, kontrak modular baru, CORS, Realtime, serta pengulangan 43 pemeriksaan UAT lulus. Tes kontrak modular memeriksa akses ditolak untuk tab terlindungi, fallback tujuh role, 61 pemetaan rute/alias, dan rendering slot kerangka/loading/placeholder. Pemeriksaan sintaks/kontrak ini tidak menggantikan pengujian semua aksi pengguna.

Chrome/CUA dengan sesi UAT baru mengonfirmasi dua halaman tersisa, interaksi filter OTW, filter Meta, dan compare. Matriks Advertiser diperiksa secara visual pada viewport 400 piksel; kartu, filter dan tabel dapat dibaca dengan scroll. Halaman pengaturan channel tetap tampil menggunakan kerangka bersama. Total 49 halaman merupakan cakupan render kumulatif audit dan tindak lanjut, bukan klaim semua operasi/role/perangkat sudah diuji end-to-end.

## Uji kesetaraan WhatsApp dan Prospek — 7 November 2026

Pemilik menegaskan target migrasi adalah fungsi VPS setara dengan aplikasi lama,
termasuk integrasi yang memang dipakai. Audit baca-saja sumber dan Meta
mengonfirmasi callback WhatsApp aktif masih menuju `meta-messaging-webhook`
sumber. Pesan/Prospek otomatis terbaru tercatat melalui Meta, sedangkan route
balasan aplikasi memanggil API Kirimdev. Jangan mengganti alur tersebut hanya
karena dua subscription Kirimdev lama berstatus nonaktif.

Pengujian terhadap bundle yang berjalan di UAT lulus 24 pemeriksaan:

- Event Kirimdev bertanda tangan menyimpan kontak, percakapan, dan pesan, lalu
  membuat satu Prospek Pending dengan asal `auto_wa_api` dan nomor ternormalisasi.
- Pemilik CS sesuai nomor WhatsApp penerima; pengiriman ulang event dan pesan
  tambahan dari kontak/CS yang sama tidak membuat Prospek terbuka ganda.
- Format webhook Meta yang dipakai sumber juga menghasilkan Prospek dan CS
  yang benar; event berulang tidak menggandakan pesan/Prospek.
- API aplikasi mengembalikan pesan yang baru masuk. Acknowledgement outbound
  tersimpan dalam percakapan yang sama dan tidak membuat Prospek baru.
- Route balasan menolak anonim; panggilan dari Owner mempertahankan tujuan,
  teks, reply context, dan idempotency key ke penyedia tiruan. Respons duplikat
  disimpan menjadi satu pesan; kegagalan penyedia tidak disimpan sebagai sukses.

Satu percobaan awal baca pesan menghasilkan HTTP 500 yang belum terklasifikasi;
percobaan ulang, pengujian setelah restart worker UAT, dan rangkaian lengkap
berhasil tanpa perubahan kode backend. Ini tidak boleh disebut bug backend yang
sudah diperbaiki; stabilitas tetap perlu diamati pada uji penerimaan live.
Percobaan pertama penyedia tiruan terhalang firewall jaringan uji. Runner kemudian
memakai aturan sementara yang hanya mengizinkan bridge UAT ke port tiruan host;
aturan dihapus dan konfigurasi firewall/gateway semula diverifikasi kembali.

Semua fixture dibersihkan. Tidak ada pesan sungguhan, perubahan callback sumber,
atau aktivasi tulis publik. Bukti privat: `kirimdev-prospects-verification.json`,
`messaging-contract-requests.json`, `source-messaging-release.json`, serta
`meta-subscriptions-release.json`. Kelulusan ini membuktikan kontrak aplikasi;
pengiriman provider sungguhan tetap harus dibuktikan saat perpindahan terkoordinasi.
